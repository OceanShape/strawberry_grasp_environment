## 슬라이드 캡션 (그대로 써도 되는 한 줄)

**A — 시연 영상 (실물 ↔ 시뮬 대조)**
> 실기 제어 스택을 하드웨어 없이 구동하고, 같은 사건(분리·영역 이동·배치)을 실물 클립과 나란히 놓았다.
> 시뮬 쪽 접근 오차는 감추지 않았다 — 접근이 빗나가면 과실도 빗나간 채 매달린다.
> 과실 배치를 바꾼 런(A-5)도 같은 코드가 끝까지 돈다. 닿지 않는 과실은 건너뛰고, 이송이 거부되면 떨어진다 — 그대로 보인다.

**B — 아키텍처**
> 실기 파이프라인과 시뮬 파이프라인은 **양 끝단(비전 입력·로봇 제어 출력)만 다르다.**
> 경계를 ROS 2 인터페이스 계약으로 잡았기 때문에, 가운데 모션 플래너 2노드는 상대가
> 실물인지 시뮬인지 알지 못한 채 동작한다.

**C — 문제 해결 Before/After**
> 통합 테스트가 실제로 잡아낸 결함 4건. 모든 수치는 실행 로그 또는 USD·URDF 실측값이며
> 출처를 패널마다 적었다. ④는 기하 검증까지 끝났고 실행 검증은 남아 있다.

**D — USD 레이어 구조**
> 임포트·순정 애셋은 읽기 전용으로 두고 커스터마이징은 전부 상위 레이어의 오버라이드로 처리했다.
> URDF를 재빌드해 임포트 산출물이 통째로 교체돼도 수정 내역이 살아남는다.

**E — 정량 지표**
> 숫자마다 출처와 재생성 명령을 붙였다. 면접에서 되짚어 물어도 그 자리에서 열어 보일 수 있다.

## 권장 슬라이드 순서

1. 프로젝트 한 줄 정의 + 기술 스택 (`PROJECT_SUMMARY.md` §1·§2)
2. **B** 아키텍처 — "무엇을 만들었나"
3. **A** 시연 영상 — "실제로 돈다" (A-4 전체 수확 → A-1/A-2/A-3 실물 대조 쌍)
4. **C** Before/After — "어떻게 디버깅했나" (이 프로젝트에서 가장 강한 슬라이드)
5. **D** USD 레이어 — "협업 가능한 구조로 만들었나"
6. **E** 정량 지표 + 잔여 이슈 — "정직하게 안다"
7. (부록) 발표 영상 링크 — 전체를 대조하지 않는다. 발표 영상에는 시뮬에 없는 병든 딸기 분기가 있다

> 4번이 핵심이다. 시뮬레이션 포트폴리오에서 변별력은 "돌아간다"가 아니라
> **"안 돌아갈 때 원인을 어떻게 좁혔나"** 에서 나온다.

### 런마다 하는 일

1. **남은 노드부터 확인한다** — 옛 노드가 살아 있으면 코드로 안 보이는 오동작이 난다:
   ```bash
   ps -ef | grep -E "fake_vision|sim_executor_bridge|curobo_planner|scan_executor|status_monitor" | grep -v grep
   ```
   하나라도 나오면 [`docs/run_guide.md`](../docs/run_guide.md) "전체 종료 / 재실행 전 초기화" 를 먼저 한다.
2. **씬을 다시 로드한다** — USD 를 고쳤으면 노드 재시작만으로는 반영되지 않는다.
   **런 3(배치 변경)**: 재로드 전에 `python3 strawberry_harvest/scripts/scene_tools/gen_random_layout.py --seed 4 --apply`. 런 3 이 끝나면 `--restore` 하고 `git diff --stat strawberry_harvest/scenes/layers/` 가 비었는지 확인한다. 런 순서를 3 → 1 → 2 로 해도 되지만, 어느 쪽이든 배치가 바뀔 때마다 재로드다.
3. [`docs/run_guide.md`](../docs/run_guide.md) 순서대로 **T1(Isaac: 브릿지 + 뷰포트 표시 `isaac_sim_viewport_display.py`) → T2 → T3 → T4** 를 띄운다.
   시뮬 전용 파라미터는 run_guide 의 T3 명령에 이미 들어 있다 (`ee_to_tcp_offset_m:=0.236`, `enable_open_stem_descent:=true`).
   T2(브릿지)에는 `tool_tcp_offset_m` 을 **지정하지 않는다** (기본값 0.236 이 T3 와 한 쌍).
4. **기동 로그 두 줄을 눈으로 대조한다** (안 보이면 파라미터가 안 먹은 것):
   - T3 플래너: `EE_TO_TCP_OFFSET_OVERRIDE: 160mm -> 236mm`
   - T2 브릿지: `GRASP_JUDGE_MODEL: tool_tcp_offset=236mm ...`
   두 값이 **같아야** 한다. 다르면 딸기를 제대로 잡아도 전부 빈손 판정이 난다. 나머지 대조 줄은 run_guide "기동 직후 눈으로 대조할 5줄".
5. 뷰포트 카메라를 이 런의 앵글로 맞추고, 화면 녹화를 시작한 뒤 **T5 트리거** (`/strawberry/scan/start`).
   **창은 1920×1080, 축소 없이 1:1 로 캡처한다** (아래 "편집 · 해상도와 크롭").
6. 확인할 것: `clamped` WARN 없음, `JOINT_COMMAND_REJECTED` 없음, 화면상 관통 없음, HUD 단계 표시가 진행에 맞게 바뀜, HUD 트리 노드가 순회 순서대로 켜짐(제외·분할·세부 칸), 좌하단 그리퍼 카메라 창이 뜨고 Kit 콘솔 `[wrist_cam] ... fov 79.41 x 63.83 deg` 확인.
7. 끝나면 로그를 `log/m3/` 로 보존한다 (`~/.ros/log/` 의 최신 파일을 노드별로 이름 붙여 복사).
   `log/m2_5/README.md` 와 같은 형식으로 런 요약 한 장을 같이 남기면 C·E 갱신(T6)이 쉽다.
   롱샷 런과 클로즈업 런은 하위 폴더로 나눈다 (`log/m3/run1_long/`, `log/m3/run2_close/`, 배치 변경 런은 `log/m3/run3_layout_seed4/`).

### 편집

**원칙 — 증거는 HUD, 자막은 읽는 법 안내.** 가지치기·분할·파지·배치·낙하는 실행 중 HUD 에 찍힌 것만 증거로 쓴다(09-11 결정: 후편집 오버레이 금지).
자막은 그 순간 화면의 어디를 보면 되는지만 알려 준다. HUD 에 없는 판정이나 결과를 자막으로 만들지 않는다.

- **녹화는 매 런 HUD 포함 전체 창으로 한다.** 클립별로 편집에서 자른다. 잘라내기는 나중에 되지만, 없는 걸 넣을 수는 없다.
- 녹화 전 10초 정도 테스트 녹화를 한다. 최종 출력 해상도에서 HUD 트리 라벨이 읽히는지 확인한다. HUD 패널은 좁게, 뷰포트는 크게 둔다.

**해상도와 크롭 (2026-09-16 추가) — 원본은 1080p, 좁은 자리에 넣을 때는 축소가 아니라 크롭이다.**

- **녹화는 Kit 창을 1920×1080 에 맞춰 1:1 로 캡처한다.** 더 큰 창을 1080p 로 줄여 녹화하면 HUD 글자가 그 비율만큼 작아진다 — 2560 창이면 24px 글자가 18px 이 된다. 녹화 해상도와 출력 해상도를 같게 두면 위 테스트 녹화의 판정이 그대로 최종본에 적용된다.
- **슬라이드에서 작게 재생되더라도 소스는 1080p 그대로 둔다.** PPT 안에서 60% 폭으로 재생하는 것과 소스를 줄여 두는 것은 다르다. 소스가 선명해야 흐릿하게 안 보인다.
- **비교 클립(반폭 나란히)은 전체 프레임을 줄이지 않는다.** 절반으로 줄이면 HUD 글자가 12px 이 돼 읽히지 않는다. 보여 주려는 것이 동작이므로 **HUD 를 아예 잘라내고 팔 + 보드 영역만 4:3 또는 1:1 로 크롭해 원본 픽셀 밀도 그대로** 붙인다. 실물 클립도 같은 비율로 잘라 옆에 둔다 — 같은 크기의 같은 영역이라 동작 비교가 직관적이다.
- A-4: 롱샷 런(HUD 포함)을 메인으로 30~60초. 파지 순간마다 클로즈업 런의 같은 구간을 인서트. 자막은 HUD 가 바뀌는 순간에 맞춘다(SE 가 흐려질 때 `SE — 익은 과실 없음, 제외`).
- A-1/A-2/A-3: 시뮬 구간(5~10초)과 실물 클립을 나란히. 같은 사건, 같은 길이로 맞춘다. 화면이 둘로 나뉘므로 시뮬 쪽은 위 "해상도와 크롭" 대로 **뷰포트만 크롭**해 원본 픽셀 그대로 쓴다(HUD 까지 넣으면 로봇이 너무 작다). 양쪽 위 모서리에 `실물` / `시뮬` 고정 라벨을 둔다.
- A-5: 런 3 롱샷(HUD 포함)을 20~40초로. 건너뛴 과실(`ABORT` 뒤 다음 과실로 넘어가는 장면), 낙하, 계란판 착지 어긋남을 자르지 않는다. 분할 분면이 시연 배치와 다르다는 것은 HUD 트리가 보여 준다. 자막은 그 차이를 가리키기만 한다.
- **실패 장면은 자르지도 흐리지도 않는다.** 자막은 화면에서 일어난 사실만 적는다(`이송 계획 거부 → 트레이 밖에서 놓음, 낙하`). 원인 설명은 슬라이드와 H §9·§10 에서 한다.
- 영상은 리포 밖에 두고 링크만 문서에 적는다.

### 자막 규칙

| 항목 | 규칙 |
|---|---|
| 방식 | **번인**(영상에 굽기). PPT 에 넣으면 별도 자막 파일은 안 보인다. 원본은 클립별 `.srt` 로 영상 폴더에 같이 둔다(리포 밖) — 문구를 고치면 다시 굽는다 |
| 모양 | 흰 글씨 + **반투명 검은 상자(불투명도 60~70%)**. 완전 불투명 상자는 바닥 낙하·계란판 착지 같은 화면 아래쪽 사건을 가린다 |
| 위치 | **화면 하단 가운데** — HUD 패널(좌상단)과 그리퍼 카메라 창(좌하단) 사이로 비는 자리다. 상자 폭은 화면 폭의 **40% 안쪽**(1080p 기준 ~770px = 한 줄 16자 × 44px)으로 잡아 좌하단 창에 안 걸친다. 완료 줄 `배치 n · 낙하 m` 을 가리면 안 된다. 낙하·착지가 아래쪽에서 나는 구간은 위로 올린다. 그리퍼 카메라 창 480×360(09-16 S5) 기준 창 오른쪽 끝은 화면 폭 27%, 40% 자막 상자의 왼쪽 끝은 30% — 여유 3%p(≈60px). **창 크기를 바꾸면 이 여유를 다시 확인한다** |
| 글꼴 | HUD 라벨과 같은 **Noto Sans CJK KR**, 1080p 기준 40~48px, 굵기 Medium |
| 색 | 흰색 한 가지. 하늘색(`#81B8DC`)은 HUD 트리와 보드 테두리에서 "로봇이 있는 곳"이라서 자막에 쓰지 않는다(09-16 까지는 주황이었다) |
| 분량 | 한 줄 16자 안팎, 최대 2줄, 한 자막 최소 2초. 사건이 먼저 보이고 자막은 0.3초쯤 뒤에 뜬다 |
| 용어 | HUD 표기를 그대로 쓴다: `NW·NE·SE·SW`, 제외·잎·분할, `배치 n · 낙하 m` |
| 클립 머리 | 첫 2초만 왼쪽 위에 제목 한 줄(`A-5 · 배치 변경 (시드 4)`). 계속 띄워 두지 않는다 |
